🧠 What is a Stored Procedure?

A stored procedure (SP) is a block of SQL code saved inside the database that performs a specific task (like insert, update, delete, select).
Instead of writing the same SQL repeatedly, you store it once and just call it whenever needed.
syntax:

CREATE PROCEDURE procedure_name (parameter_list)
BEGIN
    -- SQL statements
END;

to run it:
CALL procedure_name(parameter_values);

🔹 Why use Stored Procedures?

| Benefit                | Description                                               |
| ---------------------- | --------------------------------------------------------- |
| 🚀 **Performance**     | SPs are precompiled → execute faster.                     |
| 🔒 **Security**        | You can give EXECUTE access only, hiding table structure. |
| 🔁 **Reusability**     | Same logic reused by many applications.                   |
| 🧩 **Maintainability** | Changes done in one SP → reflect everywhere.              |
| 🧱 **Encapsulation**   | Combines business logic + SQL in one place.               |

🧠 What are Parameters?

Parameters let you pass values to or from a stored procedure — just like arguments in a function.

🅰️ 1️⃣ IN Parameters
🧩 Meaning:

IN parameters are used to send values into a stored procedure.

You cannot modify or return them — they are read-only inside the SP.
✅ Syntax:

CREATE PROCEDURE procedure_name (IN parameter_name datatype)
BEGIN
    -- use the parameter
END;

1️⃣ IF…ELSE: and Nested IFs

✅ Syntax:

IF condition THEN
    -- statements
ELSEIF another_condition THEN
    -- statements
ELSE
    -- statements
END IF;

1	Riya	20000

⚙️ GOAL

We want a Stored Procedure that:

Takes EmpID as input.

Fetches the employee’s salary.

Prints a message like:

If Salary > 100000 → "High Salary"

If Salary between 50000 and 100000 → "Medium Salary"

If Salary < 50000 → "Low Salary"

✅ Stored Procedure Example (IF + Nested IF)
CREATE PROCEDURE CheckEmployeeSalary(IN p_EmpID INT)
BEGIN
    DECLARE v_Salary DECIMAL(10,2);

    -- Get the employee salary from table
    SELECT Salary INTO v_Salary
    FROM Employee
    WHERE EmpID = p_EmpID;

    -- Main IF...ELSE logic
    IF v_Salary > 100000 THEN
        MESSAGE 'High Salary Employee';
    
    ELSEIF v_Salary BETWEEN 50000 AND 100000 THEN
        MESSAGE 'Medium Salary Employee';

    ELSE
        -- Nested IF inside ELSE
        IF v_Salary < 25000 THEN
            MESSAGE 'Very Low Salary Employee';
        ELSE
            MESSAGE 'Low Salary Employee';
        END IF;
    END IF;
END;

IF		Checks one condition		IF v_Salary > 100000 THEN ...
ELSEIF	Adds more conditions		ELSEIF v_Salary BETWEEN 50000 AND 100000
ELSE	Executes if no condition matched		ELSE MESSAGE 'Low Salary'
Nested IF	Extra checks inside an IF block		IF v_Salary < 25000 THEN ... END IF;

⚙️ GOAL

We’ll build a stored procedure that:

Takes EmpID as input

Reads the employee’s salary

Uses a CASE statement to decide the Salary Category

> 100000 → High Salary

50000–100000 → Medium Salary

< 50000 → Low Salary

Updates the SalaryCategory column in the table

Displays a message showing the category assigned.

✅ Stored Procedure Using CASE
CREATE PROCEDURE SetSalaryCategory(IN p_EmpID INT)
BEGIN
    DECLARE v_Salary DECIMAL(10,2);
    DECLARE v_Category VARCHAR(30);

    -- Get employee salary
    SELECT Salary INTO v_Salary
    FROM Employee
    WHERE EmpID = p_EmpID;

    -- Use CASE to decide the category
    SET v_Category = 
        CASE
            WHEN v_Salary > 100000 THEN 'High Salary'
            WHEN v_Salary BETWEEN 50000 AND 100000 THEN 'Medium Salary'
            ELSE 'Low Salary'
        END;

    -- Update the table with the decided category
    UPDATE Employee
    SET SalaryCategory = v_Category
    WHERE EmpID = p_EmpID;

    -- Show confirmation message
    MESSAGE 'Employee ' || p_EmpID || ' categorized as ' || v_Category;
END;

🔁 1️⃣ What is a WHILE Loop?
A WHILE loop in SQL Anywhere is used to repeat a block of code as long as a specified condition is true.

🧠 2️⃣ Basic Syntax

WHILE condition DO
    -- statements
END WHILE;
CREATE PROCEDURE SetSalaryCategoryWHILE()
BEGIN
    -- Step 1: Declare variables
    DECLARE v_EmpID INT DEFAULT 1;       -- start from first EmpID
    DECLARE v_Salary DECIMAL(10,2);     -- store salary of current employee
    DECLARE v_Category VARCHAR(30);     -- store calculated category
    DECLARE v_MaxEmpID INT;             -- store maximum EmpID

    -- Step 2: Get maximum EmpID to know when to stop
    SELECT MAX(EmpID) INTO v_MaxEmpID FROM Employee;

    -- Step 3: Start the WHILE loop
    WHILE v_EmpID <= v_MaxEmpID DO

        -- Step 3a: Get salary of current employee
        SELECT Salary INTO v_Salary
        FROM Employee
        WHERE EmpID = v_EmpID;

        -- Step 3b: Decide category using IF...ELSE
        IF v_Salary > 100000 THEN
            SET v_Category = 'High Salary';
        ELSEIF v_Salary BETWEEN 50000 AND 100000 THEN
            SET v_Category = 'Medium Salary';
        ELSE
            SET v_Category = 'Low Salary';
        END IF;

        -- Step 3c: Update table with category
        UPDATE Employee
        SET SalaryCategory = v_Category
        WHERE EmpID = v_EmpID;

        -- Step 3d: Increment EmpID to move to next row
        SET v_EmpID = v_EmpID + 1;

    END WHILE;  -- loop ends when v_EmpID > v_MaxEmpID
END;

▶️ Execution
CALL SetSalaryCategoryWHILE();

🧠 What Happens Step by Step

v_EmpID = 1, v_MaxEmpID = 4

Loop checks 1 <= 4 → TRUE → enters loop

Gets salary for EmpID = 1 → 20000 → Low Salary → updates table

v_EmpID = 2 → checks 2 <= 4 → TRUE → repeat

Loops through EmpID = 3, 4

v_EmpID = 5 → checks 5 <= 4 → FALSE → loop stops 
You can also use:

LEAVE to break out of the loop

CONTINUE to skip to the next iteration

🌀 1️⃣ REPEAT Loop
🧠 Concept

The REPEAT loop always executes the block at least once,
then checks the condition at the end of the loop.

If the condition is FALSE, the loop continues.

If the condition is TRUE, the loop stops.

Think of it like a “do...while” loop in C / Java / C#.

✅ Syntax
REPEAT
    -- statements to execute
UNTIL condition
END REPEAT;


📌 Difference from WHILE:

WHILE checks condition before executing → may never run.

REPEAT checks condition after executing → runs at least once.
✅ Stored Procedure Example
CREATE PROCEDURE SetSalaryCategoryREPEAT()
BEGIN
    DECLARE v_EmpID INT DEFAULT 1;
    DECLARE v_MaxEmpID INT;
    DECLARE v_Salary DECIMAL(10,2);
    DECLARE v_Category VARCHAR(30);

    -- Get max employee ID to know when to stop
    SELECT MAX(EmpID) INTO v_MaxEmpID FROM Employee;

    -- Start REPEAT loop
    REPEAT
        -- Get salary for current EmpID
        SELECT Salary INTO v_Salary
        FROM Employee
        WHERE EmpID = v_EmpID;

        -- Decide category
        IF v_Salary > 100000 THEN
            SET v_Category = 'High Salary';
        ELSEIF v_Salary BETWEEN 50000 AND 100000 THEN
            SET v_Category = 'Medium Salary';
        ELSE
            SET v_Category = 'Low Salary';
        END IF;

        -- Update category in table
        UPDATE Employee
        SET SalaryCategory = v_Category
        WHERE EmpID = v_EmpID;

        -- Increment counter
        SET v_EmpID = v_EmpID + 1;

    UNTIL v_EmpID > v_MaxEmpID  -- Condition to stop
    END REPEAT;
END;

▶️ Execution
CALL SetSalaryCategoryREPEAT();

1️⃣ DECLARE Variables Inside Stored Procedure


Variables are temporary containers used to store data within a procedure
In SQL Anywhere, you must declare them before using them (at the top of your BEGIN...END block).
ou define them with DECLARE, assign values with SET, and read/write with SELECT INTO.
syntax:
DECLARE @variable_name data_type;

Let’s create a procedure to calculate an employee’s annual salary.
CREATE PROCEDURE CalculateAnnualSalary()
BEGIN
    DECLARE @monthlySalary DECIMAL(10,2);
    DECLARE @annualSalary DECIMAL(10,2);

    SET @monthlySalary = 50000;
    SET @annualSalary = @monthlySalary * 12;

    SELECT 'Annual Salary is: ' || @annualSalary AS Result;
END;

CREATE PROCEDURE ShowTaxCalculation(IN p_ProductID INT)

    SELECT Quantity INTO v_qty FROM Product WHERE ProductID = p_ProductID;

    IF v_qty < 5 THEN
        SELECT 'Low Stock' AS Status;
    ELSE
        SELECT 'In Stock' AS Status;
    END IF;
END;

2️⃣ Local vs Procedure-Level Variables:

Local variables → Declared inside a BEGIN...END block, used only within that block.

Procedure-level variables → Declared at the top level of the procedure (before nested BEGIN...END blocks), accessible throughout the procedure.

CREATE PROCEDURE ExampleLocalVsProcedureLevel()
BEGIN
    -- Procedure-level variable
    DECLARE @baseSalary DECIMAL(10,2);
    SET @baseSalary = 40000;

    BEGIN
        -- Local variable (visible only inside this BEGIN...END)
        DECLARE @bonus DECIMAL(10,2);
        SET @bonus = 5000;

        SELECT 'Inside block: ' || (@baseSalary + @bonus) AS TotalPay;
    END;

    -- Trying to use @bonus outside gives an error
    SELECT 'Outside block: ' || @baseSalary AS SalaryOnly;
END;

4️⃣ Assigning Values using SET
The SET statement assigns a value to a variable.

SET @variable_name = expression;
SET @count = 5; example

You can also assign directly from a query using SELECT ... INTO.


SELECT Salary INTO @salary FROM Employee WHERE EmpId = 101;

CREATE PROCEDURE CalculateBonus(@empId INT)
BEGIN
    DECLARE @salary DECIMAL(10,2);
    DECLARE @bonus DECIMAL(10,2);

    SELECT Salary INTO @salary FROM Employee WHERE EmpId = @empId;
    SET @bonus = @salary * 0.10;

    SELECT 'Employee ID: ' || @empId AS Emp, 'Bonus: ' || @bonus AS BonusAmount;
END;

✅ Conclusion

SET → good for constants, simple calculations, single variable assignment.

SELECT INTO → good for assigning values from a table, multiple variables, and queries.


🔹 1️⃣ BEGIN TRANSACTION / COMMIT / ROLLBACK

Transactions in stored procedures make sure that:

All SQL statements inside the SP succeed together, or

If any one statement fails, all previous changes are rolled back.
🧩 Syntax
BEGIN TRANSACTION;

-- your SQL operations here

COMMIT;   -- saves the changes permanently
-- or
ROLLBACK; -- undo all changes


with stored procedure syntax:
CREATE PROCEDURE procedure_name()
BEGIN
    BEGIN TRANSACTION;

    -- SQL operations (Insert / Update / Delete)

    IF condition THEN
        COMMIT;  -- everything succeeded, save changes
    ELSE
        ROLLBACK; -- something failed, undo changes
    END IF;
END;

Let's imagine two customers — A and B.
We’ll transfer ₹5000 from A → B safely using a stored procedure.


CREATE PROCEDURE TransferMoney(
    IN fromAcc INT,
    IN toAcc INT,
    IN amount DECIMAL(10,2)
)
BEGIN
    DECLARE @fromBalance DECIMAL(10,2);

    -- Start the transaction
    BEGIN TRANSACTION;

    -- Step 1: Check if sender has enough balance
    SELECT Balance INTO @fromBalance
    FROM Accounts
    WHERE AccNo = fromAcc;

    IF @fromBalance >= amount THEN
        -- Step 2: Deduct from sender
        UPDATE Accounts
        SET Balance = Balance - amount
        WHERE AccNo = fromAcc;

        -- Step 3: Add to receiver
        UPDATE Accounts
        SET Balance = Balance + amount
        WHERE AccNo = toAcc;

        COMMIT;  -- ✅ all successful
    ELSE
        ROLLBACK;  -- ❌ not enough balance
    END IF;
END;

✅ With transaction → atomic & safe
❌ Without transaction → partial & risky

🔹 2️⃣ Locking Tables or Rows

When two users access the same data at the same time, locks prevent data corruption.

🔒 Types:

Row-level lock: locks only the row being modified → allows high concurrency.

Table-level lock: locks the entire table → ensures safety but reduces concurrency.
BEGIN TRANSACTION;

LOCK TABLE Employee IN EXCLUSIVE MODE;

UPDATE Employee SET Salary = Salary + 5000 WHERE Dept = 'IT';

COMMIT;
🧠 Meaning:

Prevents other users from reading/writing the Employee table until the transaction ends.

Used when you are doing bulk updates/deletes.

👉 Error Handling in Stored Procedures.

1️⃣ BEGIN…EXCEPTION…END Blocks
🧩 Syntax:
BEGIN
    -- Normal SQL statements
EXCEPTION
    WHEN OTHERS THEN
        -- Error-handling logic (like ROLLBACK, custom message, etc.)
END;
🧩 Example 1: Simple Try–Catch style
CREATE PROCEDURE DivideNumbers(a INT, b INT)
BEGIN
   DECLARE result DECIMAL;
   BEGIN
      SET result = a / b;
      MESSAGE 'Result = ' || result TO CLIENT;
   EXCEPTION
      MESSAGE '❌ Error: Division by zero or invalid input' TO CLIENT;
   END;
END;

CALL DivideNumbers(10, 2);  -- Output: Result = 5
CALL DivideNumbers(10, 0);  -- Output: ❌ Error: Division by zero or invalid input

🧩 Example 2: Handling specific SQLSTATE
CREATE PROCEDURE SafeInsert()
BEGIN
   BEGIN
      INSERT INTO Employee(EmpId, EmpName)
      VALUES (1, 'John'); -- Suppose EmpId=1 already exists
   EXCEPTION
      WHEN SQLSTATE = '23505' THEN
         MESSAGE 'Duplicate Key Error: Employee already exists!' TO CLIENT;
      WHEN OTHERS THEN
         MESSAGE 'Some other error occurred.' TO CLIENT;
   END;
END;

CALL SafeInsert();

CREATE PROCEDURE UpdateEmployeeSalary_Complex(
    IN p_empId INT,
    IN p_newSalary DECIMAL(10,2)
)
BEGIN
    DECLARE @oldSalary DECIMAL(10,2);
    DECLARE @message VARCHAR(200);

    BEGIN
        -- Start transaction
        BEGIN TRANSACTION;

        -- Step 1: Check if employee exists
        SELECT Salary INTO @oldSalary
        FROM Employee
        WHERE EmpId = p_empId;

        IF @oldSalary IS NULL THEN
            SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Employee ID not found!';
        END IF;

        -- Step 2: Validate salary
        IF p_newSalary < 10000 THEN
            SIGNAL SQLSTATE '45001'
            SET MESSAGE_TEXT = 'New salary must be at least 10,000.';
        END IF;

        -- Step 3: Update salary
        UPDATE Employee
        SET Salary = p_newSalary
        WHERE EmpId = p_empId;

        -- Step 4: Log the change
        INSERT INTO SalaryLog(EmpId, OldSalary, NewSalary)
        VALUES (p_empId, @oldSalary, p_newSalary);

        COMMIT;
        MESSAGE 'Salary updated successfully for employee ' || p_empId TO CLIENT;

    EXCEPTION
        WHEN SQLSTATE '45000' THEN
            SET @message = 'Error: Employee not found.';
            ROLLBACK;

        WHEN SQLSTATE '45001' THEN
            SET @message = 'Error: Salary below minimum value.';
            ROLLBACK;

        WHEN SQLSTATE '23000' THEN
            SET @message = 'Duplicate or constraint violation.';
            ROLLBACK;

        WHEN OTHERS THEN
            SET @message = 'Unexpected error: ' || SQLERRORTEXT();
            ROLLBACK;
    END;

    -- Step 5: Log all errors (if any)
    IF @message LIKE 'Error%' THEN
        INSERT INTO ErrorLog(ProcedureName, ErrorMessage, SqlStateCode)
        VALUES ('UpdateEmployeeSalary_Complex', @message, SQLSTATE);
        MESSAGE @message TO CLIENT;
    END IF;

END;

🧩 1️⃣ INNER JOIN in Stored Procedure

👉 Use case: Get all orders with their customer details.

CREATE PROCEDURE GetAllOrdersWithCustomers()
BEGIN
    SELECT 
        O.OrderID,
        C.CustomerName,
        C.City,
        O.ProductName,
        O.Quantity,
        O.TotalAmount
    FROM Orders AS O
    INNER JOIN Customer AS C
        ON O.CustomerID = C.CustomerID;
END;

🧠 Example Usage:
CALL GetAllOrdersWithCustomers();

🧩 2️⃣ LEFT JOIN Example

👉 Use case: Show all customers, even those who haven’t placed any orders.

CREATE PROCEDURE GetAllCustomersWithOrders()
BEGIN
    SELECT 
        C.CustomerID,
        C.CustomerName,
        C.City,
        O.OrderID,
        O.ProductName,
        O.TotalAmount
    FROM Customer AS C

        ON C.CustomerID = O.CustomerID;
END;

🧠 Example Usage:
CALL GetAllCustomersWithOrders();

🧩 3️⃣ RIGHT JOIN Example

👉 Use case: Show all orders, even if the customer record is missing (rare but possible).

CREATE PROCEDURE GetAllOrdersRightJoin()
BEGIN
    SELECT 
        O.OrderID,
        O.ProductName,
        C.CustomerName,
        C.City
    FROM Orders AS O
    RIGHT JOIN Customer AS C
        ON O.CustomerID = C.CustomerID;
END;


Works similarly, but ensures right table (Customer) rows always appear.

🧩 4️⃣ FULL JOIN (Emulation)

SQL Anywhere doesn’t have a direct FULL JOIN, but you can simulate it with UNION.

CREATE PROCEDURE GetFullJoinData()
BEGIN
    SELECT C.CustomerID, C.CustomerName, C.City, O.OrderID, O.ProductName
    FROM Customer C
    LEFT JOIN Orders O ON C.CustomerID = O.CustomerID
    UNION
    SELECT C.CustomerID, C.CustomerName, C.City, O.OrderID, O.ProductName
    FROM Customer C
    RIGHT JOIN Orders O ON C.CustomerID = O.CustomerID;
END;


✅ This ensures both unmatched customers and unmatched orders are included.


⚙️ Step 6: CROSS JOIN (for completeness)

CROSS JOIN = Cartesian Product → combines each row of A with each row of B (used rarely).

CREATE PROCEDURE CrossJoinExample()

    FROM Employee E
    CROSS JOIN Department D;
END;

CALL CrossJoinExample();
